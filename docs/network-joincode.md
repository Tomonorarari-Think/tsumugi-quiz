## 1. 参加コード仕様（仮決め K9、2026-09-13 改訂: 12 文字方式）

> **改訂の理由**: 旧案（11 文字 + mod 37）はチェック文字が `* ~ $ = U` の記号になることがあり、
> 口頭伝達・手入力で扱いにくかった。統括の判断により、全文字が Crockford Base32 の 32 記号（記号なし）に
> 収まる **12 文字方式**（50bit ペイロード + 10bit チェック = 60bit）に変更した。旧案は §1.8 に残す。

### 1.1 ペイロードのビット配置

参加コードの中身は、まず **50 ビット**の整数 `V`（IPv4 + ポート）を組み立てるところから始まる。ここは旧案と同じ。

```
 bit 49 48 | 47 .................. 16 | 15 ........ 0
 ┌────────┬─────────────────────────┬──────────────┐
 │version │        IPv4 (32bit)      │  port(16bit) │
 │ 2 bit  │  a<<24|b<<16|c<<8|d       │              │
 └────────┴─────────────────────────┴──────────────┘
   = 0

 V = (version << 48) | (ipv4 << 16) | port
```

- `version = 0` は「IPv4 + ポートの直接接続」を表す。IPv6 は対象外だが、`version` が 1〜3 を取れるので将来拡張できる。
- `ipv4` はネットワークバイトオーダーと同じ並び（第 1 オクテットが上位）。

### 1.2 チェック値と 60 ビットへの結合

```
check = V mod 1021                     # 0〜1020 に収まる 10 bit 整数
W     = (V << 10) | check              # 60 bit

 bit 59 ......................... 10 | 9 ......... 0
 ┌──────────────────────────────────┬─────────────┐
 │           V（50 bit）              │ check(10bit)│
 └──────────────────────────────────┴─────────────┘
```

- `1021` は **1024 未満で最大の素数**である（`1024 = 2^10`、10 bit ちょうどに収まる最大の素数を選んだ）。
- 60 bit ÷ 5 bit = 12 文字ちょうどで、パディングが不要。上位 50 bit（10 文字）が payload、下位 10 bit（2 文字）が check にきれいに一致する（50 も 10 も 5 の倍数のため、Base32 の桁境界と一致する）。

### 1.3 Crockford Base32 のアルファベット

出典: Douglas Crockford "Base 32" <https://www.crockford.com/base32.html>

```
符号化アルファベット（32 記号）:
  0123456789ABCDEFGHJKMNPQRSTVWXYZ
  ※ I L O U を除外（I/L は 1 と、O は 0 と紛らわしいため。U は偶発的な卑語を避けるため）
```

12 文字はすべてこの 32 記号のみで構成される。**旧案にあった `* ~ $ = U` の拡張チェック記号は不要になった。**

### 1.4 誤り検出の理由（Crockford の mod 37 と同じ論法）

Crockford の原文にあるとおり、単一チェック桁の方式では「37 は 32 より大きい最小の素数」であることを使って、
1 文字の置換誤りと隣接 2 文字の入れ替えをすべて検出できる。本方式は同じ論法を、桁数が 2 文字（10 bit）のチェックに拡張したもの。

- 素数 `p` が基数 `32` と互いに素であれば（`p` が奇素数であれば自動的に成り立つ）、ペイロードの桁 `i`（重み `32^i`）を
  別の値に書き換えると、その差は `k * 32^i`（`k` は 1〜31 の非ゼロ）だけ `V` を変化させる。`32^i` は `mod p` で可逆
  （`gcd(32^i, p) = 1`）なので、`k * 32^i mod p` は `k mod p` が 0 でない限り 0 にならない。`k` は最大でも 31 で
  `p = 1021` よりずっと小さいため、**1 文字の置換誤りは必ず `check` の不一致として検出される**。
- 隣接する 2 桁 `i, i+1`（値 `a, b`）を入れ替えると、`V` の変化量は `(a - b) * (32^i - 32^(i+1)) = (a - b) * 32^i * (1 - 32)`。
  `a ≠ b` かつ `p ∤ 31`（`1021` は `31` の倍数ではない）なので、**隣接 2 文字の入れ替えも必ず検出される**。
- `p = 1021` は 10 bit（0〜1023）に収まる最大の素数なので、チェックを 2 文字（10 bit）ちょうどに収めつつ、上の性質を満たす。

### 1.5 エンコード／デコードの擬似コード

```python
import unicodedata

ALPHABET  = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"   # 32 記号
CHECK_MOD = 1021                                  # 1024 未満で最大の素数

def encode(ip: str, port: int, version: int = 0) -> str:
    a, b, c, d = (int(x) for x in ip.split("."))
    ipv4 = (a << 24) | (b << 16) | (c << 8) | d
    v = (version << 48) | (ipv4 << 16) | port      # 50 bit
    check = v % CHECK_MOD                          # 10 bit (0..1020)
    w = (v << 10) | check                          # 60 bit
    body = "".join(ALPHABET[(w >> (5 * (11 - i))) & 31] for i in range(12))
    return f"{body[0:4]}-{body[4:8]}-{body[8:12]}"  # 表示形式 XXXX-XXXX-XXXX

def normalize(s: str) -> str:                      # §1.6
    s = unicodedata.normalize("NFKC", s)           # 全角英数字・全角ハイフン・全角スペースを半角へ
    t = s.strip().upper().replace("-", "").replace(" ", "")
    return t.replace("O", "0").replace("I", "1").replace("L", "1")

def decode(s: str) -> tuple[int, str, int]:
    t = normalize(s)
    if len(t) != 12:                  raise CodeError("長さが違います")
    if any(ch not in ALPHABET for ch in t): raise CodeError("使えない文字があります")
    w = 0
    for ch in t:
        w = (w << 5) | ALPHABET.index(ch)
    check = w & 0x3FF                               # 下位 10 bit
    if check >= CHECK_MOD:            raise CodeError("コードが正しくありません")
    v = w >> 10
    if v % CHECK_MOD != check:        raise CodeError("コードが正しくありません")
    version =  (v >> 48) & 0b11
    ipv4    =  (v >> 16) & 0xFFFFFFFF
    port    =   v        & 0xFFFF
    ip = ".".join(str((ipv4 >> s) & 255) for s in (24, 16, 8, 0))
    return version, ip, port
```

`check >= CHECK_MOD`（1021〜1023）は理論上デコード可能だが正規のエンコーダーが絶対に生成しない値なので、
不正なコードとして即座に拒否する（誤り検出の追加のボーナス）。

### 1.6 入力時の正規化

デコード前に、次の順で正規化する。

0. NFKC 正規化（`string.Normalize(NormalizationForm.FormKC)`）。日本語 IME で入力された全角英数字（`６Ｂ０１`）、
   全角ハイフン `－`（U+FF0D）、全角スペース（U+3000）を半角へ畳んでから以降の手順に進む
1. 前後の空白を除去
2. 小文字 → 大文字（`ToUpperInvariant`）
3. ハイフン `-` と空白をすべて除去（Crockford 仕様は「ハイフンは可読性のために挿入でき、デコード時は無視される」）
4. `O` → `0`、`I` → `1`、`L` → `1`（Crockford のデコード別名）
5. 結果が **12 文字**でなければエラー

正規化は `TsumugiQuiz.Core`（純 C#）に置き、Unity API に依存させない。そうすれば EditMode テストで直接叩ける（network.md §10）。

### 1.8 旧案（11 文字 + mod 37。記号が混ざるため不採用）

以前の案は、50 bit の `V` を Crockford Base32 で 10 文字に符号化し、末尾に `V mod 37` のチェック文字 1 文字
（32 記号 + `* ~ $ = U` の拡張 37 記号表）を付けた **11 文字**（表示 `XXXXX-XXXXX-X`）だった。
「37 は 32 より大きい最小の素数」という同じ論法で誤り検出は成立していたが、チェック文字が約 13.5%（5/37）の
確率で記号（`*` `~` `$` `=` `U`）になり、口頭伝達・手入力の体験を損なうため、統括の判断で不採用とし、
本書 §1 の 12 文字方式（記号なし、チェックは 2 文字・mod 1021）に置き換えた。
