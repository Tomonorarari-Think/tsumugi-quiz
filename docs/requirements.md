# 要件定義

## 目的
tsumugi-quiz（友人同士で遊ぶ早押しクイズアプリ）が満たすべき機能・非機能要件を確定させ、以降の設計ドキュメント（architecture.md / question-data.md / room-settings.md / network.md / tts.md / licenses.md）が同じ前提に立てるようにする。

## 関連ドキュメント

- [question-data.md](./question-data.md) — 問題データの JSON スキーマ・エディタ仕様
- [room-settings.md](./room-settings.md) — ルーム設定項目とプリセット
- network.md — ネットワーク（NGO・参加コード・早押し判定の実装詳細、別担当作成）
- tts.md — VOICEVOX 連携・再生同期の実装詳細（別担当作成）

- docs/tasks/setup-brief.md — 統括が全エージェントに配布した共通ブリーフ（本書はこの §0 を要件として展開したもの）

## 1. 概要

- **プロジェクト名**: tsumugi-quiz
- **想定利用者**: 友人同士数人（オンライン飲み会・オフ会などでの利用を想定した少人数パーティークイズ）
- **プラットフォーム**: Windows（Unity 6000.6.0f1、ビルドターゲットは Windows Standalone のみ）
- **接続方式**: 参加者の 1 人が「ホスト」としてサーバーを兼ねたクライアントを起動し、他の参加者は表示された「参加コード」を入力して直接接続する。外部の仲介サーバーや常設インフラは使わない
- **読み上げ**: VOICEVOX の音声ライブラリ「春日部つむぎ」を用い、各クライアントがローカルで音声合成して問題文を読み上げる
- **立ち絵表示**: 春日部つむぎの公式立ち絵を画面に表示し、状態（待機・読み上げ中・正解・不正解）に応じて切り替える
- **運用方針**: 個人利用規模のため、サーバー運用費・外部アカウント登録・継続的な保守作業が発生しない構成とする

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| ホスト | クイズを主催する参加者。サーバー機能とクライアント機能を同一プロセスで兼ねる（Netcode for GameObjects の Host モード） |
| クライアント | ホスト以外の参加者が使う接続先。参加コードを入力してホストへ直接接続する |
| 司会 | ゲームの進行を操作する役割。ホストがプレイヤーを兼ねる「参加プレイヤーモード」と、進行専任で得点対象に入らない「司会専用モード」の 2 通りがある |
| プレイヤー | 早押し・回答を行う参加者。司会専用モードではホストはプレイヤーに含まれない |
| 問題セット | 1 つの JSON ファイルにまとめられた一連の問題（`setId` で識別） |
| 早押し | 問題読み上げ中または読み上げ後に、最初に反応した参加者に回答権を与える方式 |
| お手つき | 早押しで回答権を得たが誤答、または無回答でタイムアウトした状態。ペナルティの対象 |
| 参加コード | ホストの接続情報（IP アドレス・ポート）をエンコードした短い文字列。クライアントはこれを入力して接続する |

## 3. 機能要件

### ロビー・接続
- **FR-01**: ホストは「ホストとして開始」を選択すると、NGO の Host モードでサーバー機能を起動できる
- **FR-02**: ホストは UPnP による自動ポートマッピングを試行し、成功時はグローバル IP から生成した参加コードを、失敗時は手動でのポート開放手順を案内する
- **FR-03**: ホストはインターネット用（グローバル IP）とLAN 用（プライベート IP）の 2 種類の参加コードを画面に表示する
- **FR-04**: クライアントは参加コードを入力してホストへ直接接続できる
- **FR-05**: ロビー画面には接続済みプレイヤーの一覧をリアルタイムに表示する
- **FR-06**: ホストはロビーでルーム設定（§ room-settings.md 参照）を変更でき、ゲーム開始と同時に設定を確定（ロック）してクライアントへ配布する

### 出題形式
- **FR-10**: 自由入力形式（`freeText`）の問題を出題できる。回答はテキスト入力で行う
- **FR-11**: 選択式（`choice`）の問題を出題できる。選択肢は 2〜8 個
- **FR-12**: いずれの形式でも問題に画像を添付できる（画像なしの問題と混在可能）

### 早押し・判定
- **FR-20**: プレイヤーは早押しキー（既定 Space、設定変更可）で回答権を要求できる
- **FR-21**: 早押し判定はサーバー時刻を基準に行う。クライアントの受信順ではなく、各クライアントが押下した時点のネットワーク時刻をサーバーが比較して最速の押下者を決定する
- **FR-22**: ルーム設定により「読み上げ中でも押せる」「読み上げ完了後のみ押せる」を切り替えられる
- **FR-23**: 回答権を得たプレイヤーには制限時間内の回答入力（自由入力）または選択（選択式）を求める
- **FR-24**: お手つき（誤答・タイムアウト）が発生した場合、ルーム設定に応じて「次問休み」または「減点」のペナルティを適用する
- **FR-25**: お手つき後、残り時間がある場合は他のプレイヤーに回答権を再開放する（既定動作）

### 得点
- **FR-30**: 正解時・誤答時・お手つき時の得点増減をルーム設定の値に従って適用する
- **FR-31**: 現在の得点をリザルト画面・ゲーム画面に表示する

### 読み上げ・立ち絵
- **FR-40**: 問題文（`readingText`、省略時は `text`）を VOICEVOX（春日部つむぎ）で読み上げる。読み上げ ON/OFF・速度はルーム設定で変更できる
- **FR-41**: 読み上げ再生は全クライアントで同期して開始する（ホスト時刻基準）
- **FR-42**: 立ち絵は「待機 / 読み上げ中 / 正解 / 不正解」の状態に応じて切り替わる（注: #212 で場面を追加（tts.md §8.3.1））
- **FR-43**（issue #144、2026-09-30 追加・同日ユーザー承認済み）: 自由入力（早押し）形式の問題文は、ノベルゲームのように先頭から 1 文字ずつ表示する（文字送り）
  - 部屋として読み上げを行う場合（ルーム設定 `tts.enabled = true`）は、ホストの読み上げの進行に合わせる（読み上げ時間を問題文の文字数で按分する）。利用規約の同意撤回・読み上げ未準備などで**自分の PC では音が鳴らない場合も同じ時間軸で表示する**（受付開始前に全文が読めてしまわないよう、早押しの公平性を優先。統括判断 2026-09-30）
  - 部屋として読み上げが無い場合（`tts.enabled = false`、または再生開始時刻が届かないまま早押し受付が開いた）は固定速度（ルーム設定 `question.revealMsPerChar`、既定 80ms/文字・範囲 0〜500 は 2026-09-30 ユーザー承認済み、`0` で一括表示）で送る。読み上げのある部屋で時間軸が取れない場合の固定速度は 250ms/文字以上（2026-09-30 ユーザー承認済み。読み上げより速く全文が読めないように）
  - 司会の一時停止中も文字送りは読み上げ音声に追従する（音声の一時停止は未対応）
  - 誰かが早押しした瞬間に文字送りを止め、判定確定（正解・不正解）と時間切れで全文を表示する。誤答・お手つき後に受付を再開放した場合は、送りを再開する（再開の仕方は下記）
  - 途中参加や再接続の再同期では、ホストが再同期の応答に現在の問題の読み上げの時間軸を載せ、合流した PC も（読み上げは鳴らないが）同じ時間軸で途中から文字送りする。時間軸が無ければ、受付前・受付中なら受付開始から固定速度（上記の下限あり）、回答中・判定後なら全文を表示する（PR #166 再レビューで改訂）。Game View を開いた時点で出題済みだった場合も、判定前なら全文を出さず同じ時間軸で文字送りする（受付前に全文が読めてしまわないように。PR #166 レビューで改訂）
  - 誤答・お手つき後に受付を再開放した場合、読み上げのある部屋は読み上げの位置へ追いつき、読み上げの無い部屋は止めた位置から続ける
  - 選択式・司会専任の司会画面は一括表示（全文）のままとする
  - 表示は各クライアントのローカル処理で、ネットワーク同期は行わない。早押し受付の開始時刻（T0、K12）は変更しない
  - 実装・同期方式は docs/tts.md §6.8、設定項目は docs/room-settings.md §1「問題文の表示」を参照

### 問題データ
- **FR-50**: 問題は (1) 所定フォルダに配置した JSON ファイル、(2) アプリ内問題エディタ、のいずれの方法でも追加できる
- **FR-51**: 問題・画像データはホストのみが保持し、出題直前にクライアントへ配信する（正解データは配信しない）
- **FR-52**: アプリ内エディタは問題セット・問題の一覧表示、編集フォーム、画像選択、バリデーション表示、読み上げプレビューを備える（詳細は question-data.md）

### ルーム設定・プリセット
- **FR-60**: ホストはルーム設定（最大人数・問題セット・出題数・制限時間・得点・読み上げ設定など）を変更できる
- **FR-61**: ルーム設定はプリセットとして保存・読込ができる（詳細は room-settings.md）

### クレジット・権利表記
- **FR-70**: アプリ内にクレジット画面を設け、VOICEVOX・春日部つむぎ立ち絵・使用ライブラリ等の権利表記を表示する（根拠は licenses.md）

### 利用規約同意（第三者の権利保護、2026-09-13 追加）
- **FR-71**: アプリは初回起動時（後述 FR-73 の同意記録が無いか、FR-76 の再同意条件に該当する場合）に「利用規約同意」画面（`TermsView`、architecture.md 参照）を表示する。次の各規約を、本文表示または規約 URL へのリンクで提示する: (1) VOICEVOX 音声モデル利用規約 (2) VOICEVOX ONNX Runtime 利用規約 (3) 春日部つむぎ 音声規約（クレジット表記 `VOICEVOX:春日部つむぎ`） (4) 春日部つむぎ立ち絵規約（規約 URL: https://tsumugi-official.studio.site/rule2 および /rule。運営の2つのページに同様の規約が掲載されているため、両方を提示する。2026-09-13 統括判断）
- **FR-72**: 同意画面には「同意します」チェックボックスを設け、チェックが入るまで同意ボタンを無効化する
- **FR-73**: 同意が成立した時点で、同意日時・提示した各規約テキストのバージョン（各規約テキストの SHA-256 ハッシュ）・アプリバージョンを `Application.persistentDataPath/consent.json` に記録する
- **FR-74**: FR-73 の同意記録が無い（または FR-76 により無効化された）状態では、TTS（読み上げ）・立ち絵表示を利用する機能（ロビー作成・参加・ゲーム進行等）へ進めない（撤回時の適用範囲は FR-75 の注記を参照）
- **FR-75**: 設定画面またはクレジット画面から、記録済みの同意日時・同意した規約バージョンを確認できる。同画面から規約本文を再表示すること、および同意を撤回すること（撤回すると FR-74 の制限が再度適用される）ができる
  - **解釈の確定（2026-09-18、ユーザー承認、issue #127 レビュー M-4）**: 「FR-74 の制限が再度適用される」は、**ゲーム進行中の撤回**については「TTS（読み上げ）と立ち絵の利用のみ停止し、クイズの進行（問題文の表示・早押し・採点）は継続する」を意味する。FR-74 の「ゲーム進行等へ進めない」は、同意記録が無い状態で当該機能に入ろうとする時点のゲート（初回同意前、および FR-76 による再同意要求時）を指し、進行中のゲームから退出させる（ロビー／Terms へ戻す）ことまでは求めない。実装は docs/tts.md §6.6、根拠は docs/licenses.md §12 を参照
- **FR-76**: アプリに同梱する規約テキスト（`Assets/TsumugiQuiz/Resources/Terms/*.txt`）が更新されて SHA-256 ハッシュが変化した場合、既存の同意記録を無効化し、次回起動時に再同意を求める

### 司会専用モード
- **FR-80**: ホストは「司会専用モード」を選択でき、その場合ホストはプレイヤー一覧に含まれず、早押し・回答 UI の代わりに「次へ」「一時停止」「強制正解/不正解」の司会操作 UI を表示する

## 4. 非機能要件

- **NFR-01（運用コストゼロ・外部アカウント不要）**: サーバー常設・クラウドサービス・外部アカウント登録を必要としない。接続はホスト・クライアント間の直接接続のみで完結する
- **NFR-02（対応環境）**: Unity 6000.6.0f1 で開発し、ビルドターゲットは Windows Standalone のみとする。他プラットフォームは対象外
- **NFR-03（UI 実装）**: UI は UI Toolkit のみで実装する。uGUI（com.unity.ugui）はテンプレート由来の依存として残すが、コードから参照しない
- **NFR-04（早押しの公平性）**: 早押し判定は受信順に依存せず、サーバー時刻を基準とした押下時刻の比較で行う。ネットワーク遅延の差によって不公平が生じないようにする（詳細アルゴリズムは network.md）
- **NFR-05（権利表記の厳密さ）**: VOICEVOX・春日部つむぎ立ち絵などの二次利用に関わる素材は、配布元が定める利用規約・表記義務を正確に満たす。根拠 URL を licenses.md に明記する
- **NFR-06（素材の git 管理外）**: voicevox_core 本体・音声モデル・立ち絵素材など再配布条件が個別に定められた素材は `External/` 配下に置き、git 管理対象外とする
- **NFR-07（CI 不使用）**: GitHub Actions などのクラウド CI は使わない。検証はローカルスクリプト（`scripts/verify.ps1` 等）で代替する
- **NFR-08（第三者の権利保護、2026-09-13 追加）**: VOICEVOX 音声モデル・VOICEVOX ONNX Runtime・春日部つむぎ音声・春日部つむぎ立ち絵など、第三者が定める利用規約の対象となる素材を利用する場合、アプリ内同意フロー（FR-71〜FR-76）により、利用者に規約の内容を確実に提示し、同意の事実を検証可能な形で記録し、誠実かつ厳密に遵守する。同意なしにこれらの素材を利用する機能へ進めさせない
- **NFR-09（バックグラウンド動作の継続、2026-09-30 追加・issue #153。2026-09-30 ユーザー承認済み。`runInBackground: 1` で実現、PR #158）**: 参加者はオンライン飲み会・オフ会の最中に Discord 等の別アプリへ画面を切り替えながら遊ぶことを想定するため（本書冒頭・CLAUDE.md 冒頭を参照）、クライアントがフォーカスを失っても進行・画面更新・ネットワーク通信を止めない（`ProjectSettings` の `runInBackground: 1`）。フォーカスを失うとプロセスの更新が止まることを実機確認（issue #15）で実測した。この状態では NGO の送受信も止まると考えられ、切断・再接続失敗の原因になりうる

## 5. 確定済み技術決定

以下はユーザーが確定した事項（setup-brief.md §0 準拠）。変更したい場合は **理由を添えて提案し、承認を待つ** こと（無断で変更しない）。

| 項目 | 決定 |
|---|---|
| エンジン / バージョン | Unity 6000.6.0f1（Unity 6.6）、2D、ビルドターゲット Windows Standalone のみ |
| UI フレームワーク | UI Toolkit のみ。uGUI はテンプレート依存として残すがコードから参照しない |
| CI/CD | GitHub Actions は使わない。検証は `scripts/*.ps1` で代替 |

| 早押し判定 | サーバー時刻基準（受信順ではなく、クライアント押下時のネットワーク時刻をサーバーが比較） |
| TTS | voicevox_core をネイティブ同梱。各クライアントがローカル合成。話者は春日部つむぎ。再生開始はホスト時刻基準で同期。合成結果はキャッシュ |
| TTS 関連素材の管理 | voicevox_core / ONNX Runtime / Open JTalk 辞書 / vvm は git 管理外、`External/voicevox_core/` 配下 |
| 音声モデル配布方式 | 「配布 zip 同梱」「初回起動時ダウンロード」の両案を docs に併記し、規約確認後に選ぶ（未確定） → **改訂（2026-09-13）**: vvm の TERMS.txt で「アプリケーションに組み込んで再配布することができます」を確認したため、案 (a) 配布 zip 同梱を第一候補とする（両案は docs/tts.md §10 に併記のまま。最終選定は dev-workflow.md の配布パッケージ作成手順で確定） |
| 立ち絵 | 春日部つむぎ公式立ち絵（`External/tsumugi/`、git 管理外）。状態は「待機 / 読み上げ中 / 正解 / 不正解」の最低限 |
| 権利表記 | アプリ内クレジット画面。`docs/licenses.md` に根拠 URL と表記文言 |
| 問題データ形式 | JSON。`freeText` / `choice`、画像はどちらとも組み合わせ可。判定はひらがな/カタカナ・全角半角を正規化した完全一致、複数正解可、あいまい一致なし |
| 問題追加方法 | (1) 所定フォルダに JSON を置く (2) アプリ内エディタ。問題と画像はホストが保持し、クライアントへ配信 |
| ルーム設定 | 本書 §3・room-settings.md に列挙する全項目。プリセット保存・読込に対応 |

## 6. スコープ外

以下は本プロジェクトの対象外とする（将来的な要望があれば別途検討）。

- BGM の実装（SE のみ対応）
- IPv6 対応（参加コードの version ビットで将来拡張の余地は残すが、今回は IPv4 のみ）
- モバイル対応（iOS / Android 等、Windows Standalone 以外のビルドターゲット）
- 中継サーバー（リレーサーバー）を用いた接続方式（NAT 越え不可の環境は Tailscale 等の手動対応を案内するのみ）
- 判定のあいまい一致（表記ゆれの許容範囲を広げる高度な一致判定は行わない。正規化ルールの範囲内の完全一致のみ）
- 春日部つむぎ以外の話者・ボイスの追加
